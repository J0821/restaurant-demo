# 餐饮企业官网模板（六模块响应式）

一套可直接替换内容上线的餐饮门店官网模板。纯静态，无后端、无数据库、无外部依赖，双击 `index.html` 就能看。

> 当前为**演示版**：页面上的店名、电话、地址、菜品、营业时间全部是示例数据，顶部有一条可关闭的演示提示条。

## 为什么做成这样

- **手机优先**：多数客人从微信点开链接，窄屏布局先做，宽屏再放宽。
- **纯静态**：不需要服务器和数据库，打开快、不容易挂，一年托管费几十元。
- **图片本地放**：`assets/` 跟页面一起部署，不依赖外部图床，不会因为图床挂掉变一片空白。

## 本地预览

直接双击 `index.html` 即可。需要模拟真实访问时，在项目根目录起一个静态服务：

```bash
python -m http.server 8127
```

然后打开 `http://127.0.0.1:8127/`。

## 目录结构

```
restaurant-demo/
├── index.html      页面结构，六个区块自上而下
├── styles.css      全部样式，配色变量集中在 :root
├── app.js          交互脚本（导航、滚动入场、FAQ、营业状态、复制地址）
├── assets/         三张示例图：hero-interior.jpg / chef-plating.jpg / table-detail.jpg
└── README.md
```

## 六个区块

| 区块 | 位置 | 内容 |
|---|---|---|
| 导航 | `<header class="site-header">` | 品牌标记 + 五个锚点 + 电话订座 + 移动端汉堡菜单 |
| 首屏 | `<section class="hero" id="home">` | 大图背景、品牌名、一句话定位、实时营业状态、两个按钮 |
| 菜单 | `<section class="menu" id="menu">` | 四类（招牌菜 / 主食 / 饮品 / 小食），共 16 道；菜名、虚线、价格、描述、标签 |
| 主理人的话 | `<section class="quote-band">` | 大图 + 一句引言 + 署名 |
| 到店 | `<section class="visit" id="hours">` | 营业时间卡（含实时状态）+ 地址卡（含复制地址、交通提示） |
| 常见问题 | `<section class="faq" id="faq">` | 四条折叠问答，手风琴式（同时只展开一条） |

页脚 `id="contact"` 承载品牌、导航和联系方式。

## 换一家店要改哪里

按顺序改，改完搜索一遍 `你的品牌`、`000-0000 0000`、`XX 市` 确认没有残留。

| # | 改什么 | 位置 | 说明 |
|---|---|---|---|
| 1 | 页面标题与描述 | `index.html` 第 6–7 行 `<title>` / `<meta name="description">` | 标题会被搜索引擎和分享卡片使用 |
| 2 | 品牌名 | `index.html` 三处：头部 `.brand-text`、首屏 `h1`、页脚 `.footer-brand` | 中文名和英文名各一处，页脚版权行也含品牌名 |
| 3 | LOGO 字 | `.brand-mark` 与 `.footer-mark` | 现在是「店」字，换成一个汉字或换成图片 |
| 4 | 首屏文案 | `index.html` `.eyebrow` / `h1` / `.hero-lead` / `.hero-hours` | 定位句控制在两行内，窄屏不折行才好看 |
| 5 | 电话 | 共 5 处：`href="tel:00000000000"` 四个 + 显示文本 | `tel:` 后续必须是无空格纯数字，显示文本可带分隔符 |
| 6 | 地址 | 地址卡 `dd`、复制按钮的 `data-address`、页脚 `.footer-contact` | `data-address` 要写完整可粘贴的地址 |
| 7 | 交通提示 | 地址卡「交通提示」一行 | 停车、地铁、步行时间 |
| 8 | 菜品 | 菜单区四个 `.menu-cat`，每个含 4 个 `.dish` | 增删菜只需复制 `<article class="dish">` 整块；`.dish-tag` 没有就删掉 |
| 9 | 主理人署名 | `quote-band` 的 `figcaption` | |
| 10 | 营业时间 | 时间卡三行 + `app.js` 四个常量 | 见下节，两处必须一起改 |
| 11 | 常见问题 | 四个 `<details class="faq-item">` | 增删整块即可，第一条默认展开 |
| 12 | 页脚版权 | `.footer-copy` | 年份和店名 |
| 13 | 演示提示条 | `index.html` 顶部 `.demo-bar` | 正式上线时删除或改文案，同时按下方说明处理高度变量 |

## 营业状态怎么算的

`app.js` 顶部有四个常量，改店休和市段就改这里：

```js
var LUNCH_OPEN  = 11 * 60;        // 11:00
var LUNCH_CLOSE = 14 * 60 + 30;   // 14:30
var DINNER_OPEN = 17 * 60;        // 17:00
var DINNER_CLOSE = 21 * 60 + 30;  // 21:30
```

周几店休写死在 `getShopStatus()` 里（当前是 `day === 1`，即周一）。状态每 30 秒刷新一次，页面上两处状态点（首屏和到店卡）共用同一份判断。

**注意**：这套逻辑只看本地时间，不看节假日，也不看临时歇业。要支持「今天临时闭店」，得另加一个日期开关数组。

## 配色

颜色集中在 `styles.css` 的 `:root`：

| 变量 | 值 | 用途 |
|---|---|---|
| `--cream` | `#faf5ec` | 页面底色 |
| `--cream-2` | `#f1e8da` | 次级底色、分隔 |
| `--paper` | `#fffdf8` | 卡片底色 |
| `--ink` | `#26201b` | 正文与页脚底色 |
| `--ink-soft` | `#6b6055` | 次级文字 |
| `--clay` | `#b4532f` | 主强调色 |
| `--clay-dark` | `#9a4325` | 悬停态 |
| `--olive` | `#4d5b45` | 营业中状态点 |

改一整站色调，改这几个变量即可。

**例外**：菜单区在 `.menu` 段单独写了一套暖色（底色 `#fbf0df`、卡片 `#fffdf9`、价格 `#c2381b`、序号红底白字），目的是让菜品看着更有食欲。这部分是硬编码值，不走变量——改主色时要单独看 `.menu` 段，否则菜单区会和全站脱节。

## 演示提示条与高度补偿

顶部 `.demo-bar` 是固定定位，`app.js` 的 `syncDemoHeight()` 把它的实际高度写进 `--demo-h`，再由样式联动 `header` 的 `top`、`hero` 的 `padding-top` 和 `scroll-padding-top`。

三点要注意：

1. 删掉 `.demo-bar` 后，`--demo-h` 会变成 `0px`，布局自动恢复，不用手改样式。
2. 移动端媒体查询里另有一条 `html.has-demo .hero` 的覆盖规则，层级更高，改补偿值时要一起看。
3. 高度是启动时量一次，页面运行中改字号不会自动重算。

## 上线

纯静态，任何能把 HTML 放上去的地方都行：对象存储静态托管、轻量服务器装 Nginx、静态建站服务。

国内访问的硬性前提：

- 域名需完成 **ICP 备案**，网站开办后 30 日内还要做 **公安联网备案**，备案号要挂在页脚。
- 用对象存储托管时，默认域名通常强制下载而不是预览，必须绑自定义域名（备案域名）。
- 境外静态托管（如 Vercel 免费域名、Cloudflare Worker 默认域名）在国内常被墙或超时，不要用于面向国内客户的站点。

## 已知限制

- 图片是示例素材，正式交付前必须换成客户自有照片；换图要同时改 `alt`。
- 菜单区配色硬编码，与 `:root` 变量不联动（见「配色」）。
- 营业状态不识别节假日与临时歇业。
- 没有表单与后端，询盘只能靠电话和到店；需要在线留言得另加静态表单服务。
- `.screenshots/` 与 `.trae-html-share-packages/` 是生成工具的临时产物，已在 `.gitignore` 里忽略。
